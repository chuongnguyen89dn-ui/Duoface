## **CONFIRMED** exact original GOFA observation mechanism
This is established by **three independent on-disk checks**: original ARM64 instructions, imported ObjC selector stubs, and authenticated/static ObjC array + CFString bytes.

1. GOFA handler setup function at **`0x3ce1c`** calls `[NSNotificationCenter defaultCenter]` (ObjC stub `0x44be0`, authenticated selector ref) and **`addObserverForName:object:queue:usingBlock:`** (ObjC stub **`0x440a0`**, original selector ref `0x69e80`).
2. Original constant ObjC NSArray **`0x64568`** has exact **2** NSString objects, data pointer `0x640f8`. Their static decoded CFString values are **`notificationNextBoard`** and **`notificationOtherBoard`**. ARM64 `0x3ce88` takes block literal at **`0x5d598`**, and `0x3ced8` passes it in **x5** to `0x440a0` for those names.
3. Another observer passes CFString **`0x63968`**: **`notificationSpeedBoard`**, with block literal **`0x5d5b8`** as **x5** at `0x3cf38..0x3cf44`.
4. Authenticated chained on-disk function pointers inside those original blocks resolve to **`0x5d5a8 -> 0x3cfb4`** (GOFA alert callback) and **`0x5d5c8 -> 0x3d468`** (GOFA speed callback). Inside callback `0x3cfb4`, direct instruction at **`0x3d034`** invokes **`_SAGofaAlertPayload` at `0x3e93c`**; speed callback `0x3d468`, instruction **`0x3d4d4`** invokes **`_SAGofaSpeedPayload` at `0x3e38c`**.
5. Exact original observer data-flow (static): **GOFA notification names → NSNotificationCenter delivery to original registration blocks → original GOFA-specific Swift payload extractors → original collector and overlay state (subsequent normalized mapping still to verify)**.
6. ARM64 `0x3cfb4` original alert callback bounds concurrent work (atomic gate threshold 8), passes notification object to Swift payload; this is actual code, not a fabricated callback. Do not copy original implementation into independent DuoFace.
