## New verified original call-chain information

1. **Natural UIKit layout hooks native app host.** Original `CBBridgedUIAppView.layoutSubviews` @`0xac8f0` calls superclass layout @`0xac91c`, then `updateLayout` @`0xac92c`. This is an exact instruction callsite inside the same method.
2. **Original app geometry and content reference update share ONE updateLayout call.** Original `CBBridgedUIAppView.updateLayout` @`0xacc6c` calls `calculateNativeSizeForSlotRect:` @`0xacd00`, UIKit `setTransform:` @`0xacd50`, `setFrame:` @`0xacd74` (plus later conditional frame updates @`0xace5c` and `0xacecc`), then remote app content-reference setters `setContentReferenceSize:withInterfaceOrientation:` @`0xacfb0/0xacfcc` and `setContentReferenceSize:withContentOrientation:andContainerOrientation:` @`0xacfe4/0xad004`. Selector sites verified in the original method; dynamic receiver, conditions and actual touch consequences require runtime trace.
3. **Explicit refresh is ordered rather than separated across independent timers.** Original `CBBridgedUIAppView.refreshSceneLayout` @`0xade58` calls `updateLayout` @`0xade74`, then `updateSceneSettingsFrame` @`0xade84`, then `setNeedsLayout` @`0xadedc/0xadef0` and `layoutIfNeeded` @`0xadf08`. Its `updateSceneSettingsFrame` @`0xad5bc` calls `calculateNativeSizeForSlotRect:` @`0xad638`, accesses the actual remote settings, and issues `updateSettingsWithBlock:` @`0xad970..` and @`0xadacc` on guarded paths. This is **verified method-local ordering**, not a claim that no other Native12 timer or IPC exists.
4. **Split layout references a matching refresh path.** Original `CBBridgedSplitApp.layoutSplitViews` @`0x1044f8` reads `CBWindow.carPlayUsableBounds` @`0x10454c`, includes `refreshSceneLayout` selector ref @`0x104774` and `updateLayout` ref @`0x104f84`, and conditionally mutates bounds, interaction, frames and hidden views. These are **selector references** here, not a proved receiver/callback; reconstructing the indirect `objc_msgSend` register flow would be required for a direct call-edge.
5. **Window size responds to system CarPlay bounds.** Original `CBWindow.resizeWindows` @`0xb1aac` reads `carPlayScreenBounds` @`0xb1aec` and `carPlayUsableBounds` multiple times @`0xb1b0c/b1b4c/b1b58/b1b74` and later manipulates root view clipping/masks. `CBBridgeManager.receivedMetricsUpdatedNotification:` @`0x1d1400` has a `dispatch_async` call @`0x1d1484`. This does not by itself prove whether either path fires during the user's failure.
6. Previously SHA-verified original `CBWindow.createWindows` dynamically installs root-window `hitTest:withEvent:`, `pointInside:withEvent:`, `sendEvent:`; original activity notification is ahead of superclass hit-test and natural dispatch. That separate input ownership architecture remains important, but **does not by itself explain first-working-then-dead input** without a transition.

## Specific differences in .115 independent host worth testing first

- `DFSceneHost.m:358-386` first changes UIKit host `frame/transform/center` and defers a different `commitSceneGeometry` after 0.30s. `DFSceneHost.m:388-575` then updates content-reference controllers and remote FBScene frame/foreground settings, gated by owner and cached `committedReferenceSize`. `pollScene:` runs every 0.35s and `publishYouTubeState` follows, with 0.75s throttle.
- Separately, the YouTube **app-process** `DFYouTubeOrientationRelay.m:112-141` directly changes `UIWindow.frame` and `UIWindow.bounds` and requests relayout. It may request another UIKit orientation geometry update @`169-207`. Its 3s lease is normally renewed; expiration is **not proven**.
- These are distinct host and app-process geometry writers with delayed transitions. Original method-local layout/scene consistency and .115's postponed cross-process updates differ materially, but the exact causal event has not been seen on a car. A good first tap followed by a bad second tap is consistent with a later rendered-vs-hit-target discrepancy, changed root window ownership or gesture lifecycle. It is **not** proof that a 4-second logo timer locks part of YouTube.
