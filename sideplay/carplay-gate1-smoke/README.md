# DuoFace Gate 1 – isolated jailbreak CarPlay acceptance test
This is **not** DuoFace Native12 and not the combined 0.0.7 candidate. Test only the native CarPlay Home icon and system-issued UIWindowScene on an iPhone X iOS16 rootless jailbreak, DiPlay head unit.

- Single distinct package `com.duoface.carplay.gate1smoke`; unique app bundle `com.duoface.gate1smoke`; no Conflicts, Replaces, Provides or dependencies on other DuoFace QA packages. Never copies vendor binaries or images.
- Reuses *independent project own code* `sideplay/firstparty-carplay-admission` as source at build only, deriving unique bundle ID, prefs, logs and notification. It does not modify or load the existing live app's firstparty preference, unless checking for an already-enabled gate (refuses to double arm).
- Installer registers the independent iPhone test app with `uicache -p`; sets its own kill switch and does **not** restart SpringBoard. Sileo may require a one-time respring to load the new tweak process filter; no auto-respring in maintainer scripts.
- Opening the phone test app does not arm the hook. Press **BẬT thử nghiệm trong 10 phút**, acknowledge risk, and reconnect CarPlay. Consent expires in 600s; hook refuses consent beyond 900s or when kill switch exists. **TẮT NGAY** re-enables kill switch; uninstall also creates it before removing payload.
- The app shows separate logs `DuoFaceGate1SpringBoard.log`, `DuoFaceGate1CarPlay.log`, `DuoFaceGate1Scene.log`. A blue screen with "DUOFACE GATE 1 / NATIVE CARPLAY SCENE" proves genuine UIKit external window issuance; plain uicache/LS hooks alone do not.
- Do not run with another firstparty-admission beta enabled. Testing an iOS16 SpringBoard tweak can crash/safe mode; run only parked, with recovery access. No package can guarantee hardware safety before trial.
- Acceptance: one and only one CarPlay Home icon; tapping opens true CarPlay window; Dock still system-owned; disconnect/reconnect; turn off and remove without affecting installed QA/Native12/HUD8.
- **No CI test can establish physical icon, CarPlay entitlement, receiver acceptance or touch.** Do not proceed to any Native12/HUD8/dual-app feature before Gate 1 device confirmation.

## Mach-O signing safety (0.0.4~runtimeaudit1)
The previous iOS16 CarPlay Split alpha crashed with SIGILL when code-signature load-command data overlapped `__text`. Gate1 now links its UI executable with `-Wl,-headerpad,0x1000` and checks the signed 64-bit Mach-O header/load-command bounds and LC_CODE_SIGNATURE intersection with every stored section. This is a binary integrity test, not real device execution proof. Bumped package to 0.0.4~runtimeaudit1 to avoid retaining earlier smoke1 bytes in Sileo caches.

## 0.0.3 activation repair after failed device test
User screenshots show Gate1 SpringBoard/CarPlay dylibs loaded but every Enable refused before any CarPlay Home test. The former code blocked on raw legacy Enabled=true even when the legacy runtime kill switch was ON; the error message hid this case versus a failed preference write. Now only the legacy gate's EFFECTIVE consent blocks activation. If genuinely active, user explicitly authorizes pausing its existing kill switch with a Gate1-owned marker, restored when Gate1 stops or is uninstalled. No legacy binary/package or preference plist overwritten. Failure reasons are distinct, writes are read back, and the user-requested arbitrary ten-minute expiry is removed. This fixes enable plumbing, NOT verified CarPlay admission.

## 0.0.4 runtime probe (read-only)
The iPhone app now has **KIỂM TRA ĐĂNG KÝ**: it creates one UUID nonce valid 45 seconds and asks already-running SpringBoard/CarPlay dylib to report TRUE hook-ready state, exact runtime ABI, own LSApp presence and read-only DBApplicationController roster result **only if exact selector encodings match**. The response must match the same nonce, otherwise the UI explicitly says CHƯA TRẢ LỜI. No global app enumeration, no Dashboard reload/insertion, no vehicle icon-layout mutation, no fake scene, no forced respring. Source/CI PASS is not physical acceptance: still require CarPlay Home icon and UIKit-issued scene separately. Never copy unlicensed third-party modules.

## 0.0.5~roster1 (device-unverified candidate)
Adds a separate **THỬ HIỆN TRÊN CARPLAY** button: with explicit Gate1 ON, send a nonce-guarded single-own-bundle insertion request to the already-running CarPlay process. Gate1RosterBridge.m uses guarded iOS16 private selector ABIs and original FBS application roster; if a loaded DBApplicationController exists, it inserts only the Gate1 test app and sends native didAdd for Dashboard. It makes no icon-layout writes, no respring, and never touches Native12/HUD8. Result code is reported on phone. No claim of physical icon or native scene until real DiPlay device test. Kill switch prevents future admission; already-updated in-process views may require normal reconnect to reflect removal.
