## Grounded prior art
- Source comparison previously verified original OmniCar active-panes BKS1 → 1s main queue callback → BKS0. DuoNavi gates several callbacks via `isUIAppBridging`, Native12 has explicit BKS0/BKS1 and initial `screenBlankEnabled = TRUE`. Source provenance in `sideplay/audit/qa130-six-deb-display-callgraph-20261030/`.
- iOS16 iPhone X UIKit has `UIScreen displayLinkWithTarget:selector:`. Do **not** compile `UIWindowScene displayLinkWithTarget:selector:` as if introduced on iOS16: it is a much later API. We independently sample only the actual UIWindowScene's UIScreen. This probe does not drive rendering; it measures ticks. Unlike `CADisplayLink` forcing a new scene clock (impossible in old APIs), passive ticks can be missing or stopped with display sleep. If the target app is suspended, even the five-second sampling NSTimer might stop, so absence is not positive zero-Hz proof.
- QA130 source already holds an `IOPMAssertionCreateWithName(CFSTR("PreventUserIdleSystemSleep"))` session lease; this is NOT a display power assertion. No BKS method hooks in QA131.
