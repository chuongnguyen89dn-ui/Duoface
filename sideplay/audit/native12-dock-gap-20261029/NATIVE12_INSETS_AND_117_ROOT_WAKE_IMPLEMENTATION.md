- **Original precise inset algorithm**: `CBWindow.carPlayContentInsets` @`0xb0c98..0xb0ef4` first reuses a positive cached inset, optionally parses an explicit on-device `UIEdgeInsetsFromString` config, then checks `CBWindow.activeCarPlayWindow.rootWindow` and queries the actual `safeAreaInsets` (selector @`0xb0de8`, invocation @`0xb0e30`). If no positive inset can be resolved, the original machine code has a fallback `0x4050000000000000` = **64.0pt** applied to a leading inset field (register `d9`); the fallback is not the normal safe-area case. Original `CBWindow.carPlayUsableBounds` @`0xb0ef4` obtains `carPlayScreenBounds` and these content insets and subtracts the top/bottom and left/right sums. Original `CBBridgedSplitApp.layoutSplitViews` @`0x10454c` uses `+[CBWindow carPlayUsableBounds]`. Thus “original has no hardcoded fallback” would be **incorrect**; the significant difference is **system-derived insets first, fallback only when absent**, not forcing a fixed minimum on top of valid safe area.
- **Original wake owner**: a different SHA-verified extraction established original root `CBTouchPassThroughRootSceneWindow` dynamically installs `hitTest:withEvent:`, `pointInside:withEvent:`, `sendEvent:` on the CarPlay `UIRootSceneWindow` subclass; original `CBBridgedUIAppView.hitTest:` and `CBUIAppContainerView.hitTest:` notify activity before calling UIKit super. The original `CBTouchCloneView` can inject HID events; its role in regular YouTube taps has **not been proven** and is intentionally not implemented in DuoFace.
