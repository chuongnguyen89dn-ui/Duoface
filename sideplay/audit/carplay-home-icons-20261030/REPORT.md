# 2026-10-30 — Selected iPhone apps missing from system CarPlay Home (source-grounded gap)

## Requirement and current physical evidence
User reports that DuoDash / DuoNavi expose selected iPhone applications as icons on **system CarPlay Home** as well as in their own in-car picker, while current DuoFace only lists them inside DuoFace. This is an additional missing requirement: app selected on iPhone must be eligible for **both** in-DuoFace selection and CarPlay Home, not merely drawn twice as an overlay. Current QA129 touch/Play/Zoom failures remain separate. Do not describe the missing Home icon as a proven cause of rejected YouTube taps.

## Exact current first-party source read
- `sideplay/duoface-native-scene-host/DFNativeHostRootController.m`: iPhone UI's `appSwitchToggled:` writes `DFWriteEnabledAppIDs(updated.array)`; bulk controls write same `EnabledBundleIDs`.
- `DFEnabledAppsPolicy.h`: versioned first-party `com.duoface.nativehost.enabled-apps.v1.plist`; Darwin change notice is `com.duoface.nativehost.enabled-apps.changed.v1`.
- `DFAppPickerVC.m` consumes that whitelist via `DFPickerAllowsApp(app.bundleID,enabled)`. It is **in-app picker only**, not the system Dashboard/Home app registration.
- Signed native build script `sideplay/duoface-native-scene-host/build.sh` includes `DFNativeHostRootController.m`, `DFAppPickerVC.m`, `DFTouchOwnerProbe.m`, `DFCarPlayDockOwner.m`. There is no compiled third-party Home app publisher or system Home app membership/launcher.
- `Info.plist` declares `SBStarkLaunchModes` and `CPTemplateApplicationScene` for **DuoFace's own bundle**, not all `EnabledBundleIDs`.
- `sideplay/firstparty-carplay-admission/DFFirstPartyAdmission.m` and `DFFirstPartySpringBoard.m` are **historical opt-in, own-DuoFace-bundle-only experiments**; their own README explicitly says Dashboard inclusion is not proven. Do not claim that these files expose YouTube/GOFA on CarPlay Home or enable them indiscriminately.
**Verdict: two concepts are currently conflated at the UI level: selecting an app for the DuoFace pane vs publishing its launchable identity in the genuine system Home. Current source implements the first, not the second.**
