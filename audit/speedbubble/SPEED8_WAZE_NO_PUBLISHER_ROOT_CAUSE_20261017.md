## Source-level confirmed cause
- `runtime/speedbubble/DFSpeedNativeSplit8SpringBoard.mm`: the view reads `DFSpeedHUDReadBest`; when no sample decodes, it draws literal `—`.
- `runtime/speedbubble/DFSpeedTransport8.mm`: selecting Waze sets `pinned=2` and filters Darwin data to source 2. It listens to `com.duoface.speedhud.v1.waze`; Speed8 package has **no Waze producer** posting to that namespace.
- `runtime/speedbubble/DFSpeedGMapReader8.mm`: requests GMapHUD selection `com.chou.gmaphud.source.selection` and source-2 republish `com.chou.gmaphud.source.2.request`, then reads `com.chou.gmaphud.output.v1.2.{commit,selection,speed,limit}`. `RequestPinnedGMapSource` only sends a request; it does not fetch Waze's private speed or trigger a Waze callback. No compatible app-injected publisher means unavailable/expired data.
- `migration/full_payload/native_test/build_native12_speed8compact_candidate.py`: explicitly bans `WazeGMapHUDSource` and other app adapters; it replaces only one HUD dylib compared to prior Speed7 package and keeps all 42 other payload files. `dist/payload-migration/native12-speed8compact/BAO_CAO.json` reports `data_feed_live_on_device_verified=false` and 42/43 files unchanged. Sileo checksum/deployment tests only prove package integrity, **not live source data**.
- Upstream primary source `bechou0410/gmaphud` (public MIT): `tweak/waze-source.m` uses an app-local `WSVLocationGPSPosition` hook for GPS speed (native mm/s -> km/h); native speed-limit getter is guarded by **Waze 5.25.0 specific Mach-O UUID and instruction bytes**. `tweak/Makefile` lists `WazeGMapHUDSource` separately from its Google Maps renderer `GoogleMapsVietMap`. `docs/source-output-contract.md` documents the cross-process `com.chou.gmaphud.output.v1.2` Darwin wire: publisher must be running in source app, selection request is not producer, stale samples expire after five seconds. Upstream is experimental and tested on another OS/device; compatibility with this iOS16 Dopamine user's currently installed Waze version is **unknown**.
