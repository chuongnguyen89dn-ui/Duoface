### Important limits and actionable source comparison

- `appProxy=present` is **NOT** membership in the CarPlay Dashboard's filtered app library. `CarPlayRole=declared` is **NOT** a valid Apple-issued CarPlay entitlement and does not cause scene issuance by itself.
- Project's `sideplay/firstparty-carplay-admission/DFFirstPartyAdmission.plist` filter injects **only into executable `CarPlay`**. No SpringBoard roster eligibility path exists in this package. That is a **verified scope gap**, not proof it is the only cause.
- Independent version-matched public source `pavunato/carsurf/sbtweak/CSSceneManifestSpoof.m` describes a separate iOS16 SpringBoard cached-values route (`LSBundleInfoCachedValues`) and CarPlay DashBoard `_proxyPassesInclusionFilter`; its readme reports working iPhone X iOS 16.7.12 RootHide. This is *comparison evidence*, **not a tested capability of DuoFace**. Do not copy vendor source or blindly reproduce global hooks; CarSurf documents cases where incorrect entitlements or scene-object substitutions crash SpringBoard.
- Current DuoFace Native Host signing file `sideplay/duoface-native-scene-host/entitlements.plist` contains `platform-application`, no-container and container-required flags, **no Apple CarPlay capability**; merely declaring `UIWindowSceneSessionRoleCarPlay` in Info.plist does not grant it. Apple CarPlay developer materials require approved category entitlements for normal, unmodified devices. This project aims at an independent jailbreak implementation rather than assuming Apple approved it.
- An additional potential mismatch in the current CarPlay getter hook: `DFEligible` checks both `expected` and `valuesExpected` against `NSNumber.class`. The external comparator validates `expected` for boolean flags and does not apply the same restriction to `valuesExpected`. **Hypothesis only**, not a demonstrated cause; collect actual observed classes/queries before changing the gate.
