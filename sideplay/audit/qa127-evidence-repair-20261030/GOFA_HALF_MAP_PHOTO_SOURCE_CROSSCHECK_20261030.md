## What the current source actually does (verified GitHub feature/duoface-qa127-evidence-repair-20261030)
1. `sideplay/duoface-native-scene-host/DFHostedMapRenderSize.h` defines `DFHostedViewportScaleForBundle` **uniformly = 0.50 for every bundle**; `DFHostedLogicalSizeForBundle` sets **logical width and height = 2x pane width and height** for every bundle. No GOFA-specific policy exists. Map list `com.apple.Maps/com.google.Maps/com.waze.iphone/vn.vietmap.live` does **not** include `com.lumi.GOFA`. This is a current first-party policy, not an original vendor size algorithm.
2. `DFSceneHost.m` `layoutScene`: `host.frame=(0,0,logical)`, `host.transform=scale(size/logical)`; `commitSceneGeometry` optionally sends native app child `setContentReferenceSize:withContentOrientation:andContainerOrientation:` and requests scene `setFrame:`. It does NOT read back GOFA app map subview bounds, map width constraints, trait adaptation, layout transaction generation, or successful GOFA app-process ACK. `media-reference-committed` logs dispatch, NOT app-confirmed size.
3. **Older archived physical log**, `Duoface/main:sideplay/log/DuoFaceSceneHost.log`, has explicit GOFA lines: `event=scene-frame-readback bundle=com.lumi.GOFA actual={{0, 0}, {375, 812}} target={{0, 0}, {476, 480}} same=0`; `event=original-native12-scene-size-dispatch bundle=com.lumi.GOFA child2=0 child3=1 main2=0`; `event=native12-scene-settings-live-contract-requested bundle=com.lumi.GOFA {{0, 0}, {476, 480}}`. These establish that DuoFace actually requested an aggressive full scene size/aspect change from GOFA, and that only one child sizing selector was accepted for dispatch. **They do not prove the GOFA map view accepted the resize or that this old log session matches the new photo.**
4. Current scene is hosted using `SBAppViewController` (iPhone app-scene bridge). GOFA also offers a supported native CarPlay app; DuoFace's generic iPhone hosted view is not necessarily that native CarPlay scene. In the *original reference architecture* Native12 `CBBridgeManager.renderSizeForBundleID:` provided per-bundle decisions; `CBBridgedUIAppView.refreshSceneLayout` coordinated layout, while OmniCar referenced logical pane/physical pane/sceneBox and native CarPlay scene. Static method presence does not authorize claiming byte-identical behavior or copying vendor implementations.
