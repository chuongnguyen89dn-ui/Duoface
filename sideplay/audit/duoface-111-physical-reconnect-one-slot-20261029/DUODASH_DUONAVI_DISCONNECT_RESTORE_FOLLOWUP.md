## Independently verified first-party source and likely failure gates
- `DFSlotWorkspacePolicy.h`: preferences `com.duoface.nativehost.workspace.v1.plist` `PhysicalBundles` four IDs, `RestoreOnReconnect` yes by default; invalid plist silently replaced by all empty defaults. `DFNative12Chrome.m` writes intent immediately if selected slot had no active hosted view, writes replacement only on real `sceneReady:`. Restore filters enabled/installed apps and active preset, sequential pending scene + retry. Native CarPlay Maps is a **separate owner** and not necessarily included in `PhysicalBundles`; native Maps lease handled separately. Thus one blank pane can arise from absent persisted bundle, allowlist skip, native-map failed lease, wrong preset, or host failure; need plist+scene logs before cause verdict.
- `DFDisconnectClosePolicy.h`: close **OFF by default** unless `CloseOnPhysicalDisconnect` strict CFBoolean true, independently of restore. Delay **10 seconds**, not DuoDash 12.
- `DFTouchOwnerProbe.m` `DFStopProbe`: hides windows, detaches Dock, snapshots `[old disconnectTerminationCandidates]`, then scene stop. `DFDisconnectCloseCapture` ignores cases: option OFF, missing/invalid session, empty verified live PID candidate, or stale native Maps lease. `DFEnsureDisconnectMonitor` persists only when Chrome present, candidates exist or initial splash flag still set; physical connection detector `DFConnectedCarDisplay` uses actual external-device IDs / CADisplay. This detector requires runtime evidence on head unit.
- `DFDisconnectCloseCoordinator.m`: after real disconnect and 10s, cancels if reconnected/setting off/generation changed; revalidates exact current PID, iPhone foreground ownership, physical connection; only then sends private RunningBoard targeted request. If private selector absent, unsupported, request rejected, PID changed or app foreground cannot be read, it **fails closed**. `RBSProcessPredicate/RBSTerminateRequest` is our own dynamically probed implementation, NOT a proven call copied from original DuoDash. ACK `VerifiedExited` needs actual PID exit; UI disappearing is not close.
- **Potential functional gap to investigate**: `DFDiscPhoneForegroundIsSafeForClose` requires a supported getter and treats the app being phone-foreground as forbidden, so YouTube playback remaining on phone may deliberately fail close; this cannot be corrected by blind kill because it might be genuine independent iPhone use. `gCandidates` is ephemeral, and captured only at scene stop, so if scene had already failed/pending before stop it may be empty even though user sees/app hears media. Verify before changing.
