# DuoFace — isolated native round divider-logo repair (2026-10-23)

## Purpose and comparison

User reports repeatedly that the circular native12 divider logo cannot be moved up/down even though prior DEBs and project handoff contain this behavior. No UI invention; use the original, already-referenced Native12 `CBDividerView.pointInside:withEvent:`, `handleMoveButtonLongPress`, `moveButtonTouchUp`, and `handlePan:` behavioral separation (existing source: `sideplay/audit/native12-wiring-20261019/WIRING_REPORT.md`). User explicitly overrides earlier duration to **three full seconds**, and logo movement must be **along the split line**, distinct from **perpendicular ratio movement**. Independent implementation: no original binary/license.

The prior source at `e6ec87b` combined `UILongPressGestureRecognizer(3.0s)` and a competing grip `UIPanGestureRecognizer` with `requireGestureRecognizerToFail:hold`, plus parent divider track pan. Historic physical touch diagnostics cited in that file: **28 UIButton TouchDown, 0 long-press callbacks**. Actual cause of the missing recognizer is not yet resolved by a runtime trace, but that recognizer path demonstrably never completed on the observed device. Repeated changes to its `allowableMovement`/z-order had not produced a working logo.

## Concrete source changes (not mere build/version edits)

- `sideplay/duoface-native-scene-host/DFNative12Chrome.m` commit [`981dad837c7aa8b92fdbb7f019015025f7931e90`](https://github.com/chuongnguyen89dn-ui/Duoface/commit/981dad837c7aa8b92fdbb7f019015025f7931e90).
- `DFNativeDividerGripButton`, the actual `UIButton` that logged TouchDown on device, now retains real `UITouch` screen coordinates through `beginTrackingWithTouch`, `continueTrackingWithTouch`, `endTrackingWithTouch`, `cancelTrackingWithEvent`. Move events arrive through `UIControlEventValueChanged` without competing logo-specific pan/hold gesture recognizers.
- The existing `logoTouchDown:` schedules a guarded **3-second timer** using an incrementing `logoHoldSerial`. A released/cancelled/ratio-dragged touch cancels that token; while the contact is still active the timer enters `logoHoldRecognized` and stores a fixed screen-coordinate touch + previous `logoFraction`.
- While held, move **parallel** to a vertical divider changes only `logoFraction` (up/down); when split is horizontal the same operation moves left/right. Touch-up saves `LogoFraction` to existing `com.duoface.nativehost.layout.v1.plist`; *does not swap apps or alter ratio*. Normal quick *perpendicular* grip motion still changes/saves the divider ratio. Stationary short tap still invokes existing Swap. Chrome four-second auto-hide is prevented during an active touch.
- Version pins updated after code/test changes: NativeHost `0.1.58~logotouch1`, integrated `com.duoface.jb.embedded 0.0.49~logotouch1`. Unrelated YouTube, Zoom, app host and Dock paths untouched.
- Source test file `sideplay/duoface-native-scene-host/tests/test_scenehost_safety.py` refreshed stale recognizer-string checks; a new `test_20261023_logo_3s_touch_stream_regression` requires actual tracking overrides, timer gate, fraction movement, separate ratio and swap, and absence of both competing grip gestures. Test commits `782808d3`, `e187689a`; version/test pin commits `b76b9321`, `832f996d`, `369f1f80`, `ddd1ec8f`, `6049555d`, `c1397581`.
