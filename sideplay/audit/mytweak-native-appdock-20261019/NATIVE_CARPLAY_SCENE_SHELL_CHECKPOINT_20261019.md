## New implementation actually committed and inspected
Branch `feature/mytweak-dashboard-activation-20261019`, based on `19506a47f1d6e1e3283cbb058365f1aa39f2edbc`.

- `sideplay/mytweak-independent-v1a/MTDashboardActivation.h/.m`: implements controlled request from SpringBoard to CarPlay using Darwin `notify_register_dispatch`, shared fixed-action prefs and short time window. Uses captured native `DBWorkspace` with `DBDashboardWorkspaceOwner`; `DBApplicationController.sharedInstance applicationWithBundleIdentifier:` checks the app is truly in native roster, then `DBMutableWorkspaceStateChangeRequest.activateApplication:` and `DBWorkspace.requestStateChange:`. Only allow own shell ID `com.duoface.mytweak.shell` or known native Dashboard Home `com.apple.CarPlay.dashboard`. Logs no workspace / app absent / request. `MTBridgeCoordinator.stopAndDisable` calls native Home request before removing host. This is a real workspace transition **request**, not proof it succeeds on iPhone X.
- **New real independent app bundle** `sideplay/mytweak-independent-v1a/shell/MTDuoFaceShell.m` plus `shell/Resources/Info.plist` / `shell/Makefile`. Declares `UIWindowSceneSessionRoleCarPlay` and `MTDuoFaceShellScene`. Produces its own `UIWindow initWithWindowScene:`, scene connect / active / background / disconnect lifecycle, and reports `window.frame/safeAreaInsets` to `/var/mobile/Library/Preferences/com.duoface.mytweak.shell-scene.plist`; file log `MyTweakShell.log`. An interim black scene with DuoFace label is *not* a fake Dock; split display still comes from existing SpringBoard scene host only when native scene geometry is verified.
- `MTCarPlayAdmission.h/.m`: independent, **only own exact shell bundle ID** admission compatibility at runtime for jailbreak iOS16; checks `LSBundleProxy` methods `entitlementValueForKey:ofClass:` and 3-argument method, and `LSBundleInfoCachedValues.boolForKey:` / opaque `entitlementValuesForKeys:` to report CarPlay capability flags to Dashboard/SpringBoard; never alters real apps' capabilities or copies upstream license binary. These are synthetic runtime flags, **not an Apple-granted entitlement**. Uses strict return signature gate, original-first and class gating.
- `MTNativeShellGeometry.h/.m`: only accepts `Producer=IndependentDuoFaceShell`, `Kind=NativeCarPlayWindowScene`, `CarPlayRole=YES`, `GeometryValid`, `NativeContentExcludesChrome=YES` based on **actual OS window content smaller than full display**, TTL 4 sec, display aspect match; rejects full-display window, stale, arbitrary 48px/64px guesses.
- `MTBridgeCoordinator.m`: when Filza `Enabled=YES` and CarPlay present, sends up to 8 native shell activation requests (3s apart) through native workspace while awaiting shell's valid scene. **Does not show any independent full-screen overlay** until native role+content proven. If native window disappears/backgrounds, `detach` shuts down the two hosted scenes; when reentered can recreate. On success, creates only one UIRootSceneWindow for the known-working SB `MTSceneHost` and sizes it to the native app window's verified usable region; Zoom also remains within that region, so cannot intentionally cover native system chrome. Existing app picker, touch, ratio, swap, two SB scene hosts unchanged.
- `V1ATweak.x`: SpringBoard self-only CarPlay admission, CarPlay process DBWorkspace capture/activation listener and context probe, no vendor binary. `Makefile` uses `SUBPROJECTS += shell`/Theos aggregate; `layout/DEBIAN/postinst` optionally registers only our app icon via `uicache`, no deleting system files. Control `Version: 0.2.5~shell1`, independent bundle, no Conflicts/Replaces. App icon assets not yet customized to Native12/Visual12.
