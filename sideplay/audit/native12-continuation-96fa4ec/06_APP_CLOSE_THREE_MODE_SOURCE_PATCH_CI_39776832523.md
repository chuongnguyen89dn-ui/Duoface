## Confirmed root cause and fix (not guessed)

**Critical actual source bug** in `DFNative12Chrome.m`: `openAppPickerForSlot:` and `openRunningAppManager` manually set `appPickerWindow.hidden=NO` then call `layoutControls`, but prior code had **no own flag** for this window. `menuAction:` closes the outer menu (`pickerVisible=NO`) first, while `layoutControls` controls only `pickerWindow` and `styleWindow`; the app picker had no consistent show/hide owner. On subsequent paths `appPickerDidCancel:`/same-selected/scene-pending/scene-failed, visibility was not state-derived. This can explain nonresponsive or blank App/Close interaction, but requires on-device confirmation.
