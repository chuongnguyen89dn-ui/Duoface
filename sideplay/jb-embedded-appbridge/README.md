## Native CarPlay menu-input relay (2026-10-20)

NativeHost `DFNativeHostSurfaceView.m` now forwards single-finger normalized begin/move/end/cancel **only** via the existing, timestamped, session-bound `MTCPBridgeWriteCommand` and Darwin notification. It requires an actual UIKit-issued CarPlay scene, active receiver layer, valid short-lived source lease and both opt-in flags; it does not consume touches when the layer is absent. The source `DFCPNativeBridgeQA.deliverPacket:` deliberately only invokes allowlisted V1BC menu `UIButton` actions, never arbitrary injected touches to YouTube, maps or other phone apps. Thus it is an **own-menu command connection**, not a verified two-app touch implementation. CI compilation is separate from real head-unit and scene tests; the unproven CarPlay app admission, native Dock and package conflict gate are unchanged. No Sileo publication or automatic respring.

## Native Dock 45-second reset correction, isolated candidate

The previous QA6 reverted both source crop and the explicitly opt-in native status window after 45 seconds, even when a real native Dashboard receiver remained active. This feature-only candidate now retains the original crop only while the same session/owner and fresh measured ACK geometry match; one missed ACK gets at most a four-second grace. Mode changes, opt-out, disconnect, a system-owned frame change or expired ACK restore only the frame this module previously changed. The third-option system native sidebar trial has at most 45 seconds to obtain its initial real receiver ACK; after that, continued use requires regularly refreshed ACK, with four-second loss cutoff. No indefinite lease based solely on the remote surface. Real device Dock stability and reconnect must still be tested; normal Sileo QA6 remains untouched. Candidate QA module `0.0.7~steadyack1`, integrated package `0.0.3~steadyack1`, no automatic installation/respring, no license code copied, CarPlay Home app admission still unresolved.

## Actual application registration for merged Sileo candidate

The prior single-package merger copied each module with `dpkg-deb -x` (which excludes DEBIAN maintainer scripts), and the NativeHost module deliberately had no uicache postinst at all. Thus the merged DEB could carry both apps without asking LaunchServices to register their bundles. Standalone NativeHost now has minimal `postinst`/`postrm` that register/unregister only `DuoFaceNativeHost.app`; the merged 0.0.5 candidate explicitly includes its own `postinst`/`postrm` registering both `DuoFaceNativeHost.app` and `DuoFaceQA.app`. Both scripts are inert on unrelated dpkg operations and do not restart SpringBoard, write prefs, flip consent, or change CarPlay admission. Test and workflow inspect scripts in the actual built control archive. This removes a concrete packaging omission but does NOT make the app CarPlay-entitled or prove Home icon / native scene. Existing combined `Conflicts/Replaces` migration risk remains. No stable Sileo publication.
