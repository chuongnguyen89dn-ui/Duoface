- Native data producer `-[CBBridgeManager runningBridgedApplications]` IMP `0x280D48`:
  - `CBDashboardSettings.sharedInstance.bridgedApps` at `0x280DA4-0x280E28` provides configured/bridged app IDs.
  - `currentApp` checks `CBBridgedSplitApp` and iterates `appViews[].bundleIdentifier` at `0x280E5C-0x281048`; builds active-slot index lookup; single-app fallback `0x28104C-0x281110`.
  - Actual process IDs are discovered through `FBProcessManager`'s `allApplicationProcesses`/`allProcesses` and `pid` at `0x281128-0x2814BC`, with `SBApplicationController` process fallback at `0x281508-0x281788`. Thus merely appearing in the app list does NOT prove there is a process or an active slot.
  - Each row's 7 data fields are assembled at `0x2820AC-0x28222C`: `bundleIdentifier`, `displayName`, `icon`, `isRunning`, `inActiveSlot`, `slotIndex`, `pid`. `isRunning` is set by comparison of PID greater than zero at `0x282124-0x282140`; `inActiveSlot` is independently based on the active-slot lookup's non-null value at `0x282130-0x282178`.
  - Sort comparator at `0x2823FC-0x2825EC` reads `inActiveSlot` first and uses `slotIndex` for active-slot ordering, otherwise compares `displayName`, so active slots are prioritized.
- Native UI renderer `-[CBMultitaskingOverlayView setupRecentAppsCardsInCardW:cardH:contentY:]` IMP `0xA678C`:
  - Reads `inActiveSlot` and `slotIndex` at `0xA70DC-0xA712C`, `pid` at `0xA7148-0xA7164`.
  - `inActiveSlot == YES`: branch at `0xA7534` chooses `OVERLAY_RUNNING_TAG` `0xA75B8`, formats the native slot-position label via helper `0x85D58` (left/right columns) and assigns `OVERLAY_RESTART_SINGLE` (Mở lại) at `0xA761C` to original `restartSingleAppTapped:`.
  - `inActiveSlot == NO && pid >= 1`: branch at `0xA7674-0xA7680` chooses `OVERLAY_PID_TAG` at `0xA769C` (display process PID), and `OVERLAY_CLOSE_SINGLE` at `0xA7734`.
  - `inActiveSlot == NO && pid < 1`: branch chooses `OVERLAY_BACKGROUND_TAG` at `0xA7700` (background/unconfirmed process state), with `OVERLAY_CLOSE_SINGLE` at `0xA7734`.
  - Native app list therefore has **three distinct display statuses**, not one uniform `Đang chạy` state. In particular, `pid < 1` does **not** establish that a process is actually running; it may be in the configured/bridged/session inventory.
