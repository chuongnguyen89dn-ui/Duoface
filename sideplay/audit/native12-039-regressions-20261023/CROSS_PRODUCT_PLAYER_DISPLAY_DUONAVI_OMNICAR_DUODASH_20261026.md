## Most important inference — three separate sizes (hypothesis, NOT proven fix)
1. **Physical pane rectangle (CarPlay pixels/points)**: owned by the independent Chrome; its `contentRect` accounts for system Dock. Split/solo/Zoom modifies pane frame.
2. **Logical app content/reference size + orientation/traits**: actual hosted iPhone app chooses YouTube/map player layout from its own scene. Host UIKit transform does not guarantee matching remote scene logical bounds/trait collection.
3. **Remote scene settings frame / hosting lifecycle**: SpringBoard/FrontBoard own the scene-diff callback and must accept any transition in the correct generation. The historical crash proves this layer is unsafe to mutate without coordinated ownership; 18 returns do not prove acceptance.

**Inference:** DuoFace .67 updates (1) and dispatches one selector in (2), but lacks a full host protocol for (2)-(3). OmniCar and SidePlay have **separate pane layout vs app-scene geometry/restore paths**. The user's clipped portrait player is more plausibly missing scene reflow, not an absent bespoke DuoFace video player. A visual-only skin would not fix Maps + YouTube simultaneously.

## New independent rendering design — plan, DO NOT IMPLEMENT BLINDLY
- **Module boundary `DFAppRenderCoordinator`** (new first-party when implementation authorized), one owner of (bundleID, physical slot, generation, sceneHandle, controller, attach/detach, viewport decision); no real SidePlay/OmniCar/DuoDash vendor classes imported. Replace/encapsulate the current split geometry operations, **not** logo, Chrome, App picker, Zoom, Dock or Style.
- **`DFPaneRenderPolicy`**: per-app selection of logical content CGSize and orientation; choose from *measured* CarPlay usable area, pane frame, app requirements, native render-size expectation, and stable content scale. Starts conservative; do not force orientation landscape on every app, do not fake video player or crop controls with `aspectFill`. An app-specific policy must be justified by recorded YouTube/70mai/Maps inputs/outputs.
- **`DFHostedSceneLifecycle`**: single scene owner and state machine CREATED→ATTACHING→STABLE→REFLOW_PENDING→VISIBLE→CLOSING. Generation revokes queued work. Coalesce after drag commit/Zoom/solo, not every pan tick. Only mutate an actual owned scene with ABI validation and recovery after mutation; no broad FBScene hooks or vendor flags; restore state on Close/reconnect after ownership proof.
- **Shared read-only geometry contract** in existing iPhone log export: `bundle,slot,mode,physicalFrame,logicalReference,sceneSettingsFrame,orientation,sceneGeneration,actualChildBounds,scale,hosting,renderPostACK` with before/after status and no personal video/account data; when private API absent, record UNAVAILABLE and don't send guessed selector. Real `renderPostACK` cannot be inferred from successful Objective-C send; needs observed scene settings/child trait readback.
- **Preserve one viewport render owner**: app host, split Chrome, Dock and system scene are different process owners, but a single coordinator decides app geometry. Do not run original OmniCar/AppData bridge hooks and new DuoFace scene writer against the *same scene* without an A/B isolation plan and explicit user device consent.
- **Prototype gates (before runtime mutation):** derive original SidePlay `SPPane.applySceneFrame`→`setSceneFrame:orientation:`→`restoreSceneFrame` actual callchain from pinned binary in controlled macOS CI; derive OmniCar `ABHost.setFrame`→`layoutPane` argument mapping and passInsets/end of transaction; scan DuoDash original DEB if archived bytes can be verified (old reports cover only prefs/bridge list); compare differences with DuoNavi 1.0.4 without license code. This defines alternative renderer that can be implemented without cloning vendor logic.
- **Acceptance after a *later* code build**: same iPhone X iOS16 and same app builds in parked CarPlay; map+YouTube each fits at ratio 1/3, 1/2, 2/3; YouTube video play/pause/seek/control sizes, app content not portrait-boxed; Maps map fills pane; Focus/solo↔split+Zoom all maintain scenes without reload or forced rotation; Split/ratio/logo vertically drags as currently PASS; Dock stays original; Close/Home/reconnect no SIGABRT. Preserve rollback public 0.0.67 and known .65.
- **No build / No Sileo** in this analysis-only request. Code changes require a reviewed implementation plan and corresponding source/CI + device test, not blind reactivation of Native12 `updateSettingsWithBlock:` or OmniCar `SBSceneView` hook.
