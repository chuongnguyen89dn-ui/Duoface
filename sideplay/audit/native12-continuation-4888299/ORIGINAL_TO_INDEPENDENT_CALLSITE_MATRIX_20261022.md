## Truy nguyên original SceneSettings block — chỉ ghi cái thực thấy, không nối bừa (lô 3)

Static disassembly source `gallery-media-imp/ORIGINAL_LAYOUT_IMP_INSTRUCTIONS.json`, `CBBridgedUIAppView.updateSceneSettingsFrame` @0xad5bc (original Dashboard SHA above):

- `ad70c–ad790`: primary controller optional `sceneHandle` selector guard, `performSelector:`, then fallback `_deviceAppViewController` `sceneHandle`; pointer nil-gated. **Do not** treat objdump's trailing "Objc message" comment as dynamic selector truth; x1/x2 register paths verify.
- `ad7bc–ad814`: `objc_setAssociatedObject` on resolved scene handle at actual literal strings `CBDuoFaceHosted` and `CBCarBridgeHosted`, bool YES; `ad840–ad8a8` analog bundleID flags. These are **original/vendor-specific side effects**, NOT a reason to copy them into independent DuoFace, and not proof screen admission.
- `ad8b0–ad96c`: tries `class_getInstanceVariable("_scene")` then `sceneIfExists` or `scene`, all guarded; no proof new independent scene owner exposes same private type. Our existing independent readiness logic uses `sceneHandle`/`sceneIfExists` with observed host state, not flags.
- `ad96c–ad984`: checks for `updateSettingsWithBlock:`. `ada90–adac0`: constructs an **NSConcreteStackBlock** at stack offset0x10 with invoke address relative to `adaa8: adr x8,#460`, captures `d8,d9`; `adac4..adacc` sends the block to resolved scene. Original extractor method ends at 0xadc74, while `adaa8 + 460decimal=0xadc74` appears to point at adjacent code **outside captured IMP range**. Thus full block invoke body/ABI/settings fields are NOT yet recovered in current seven-method artifact. **Do not synthesize block**, call `updateSettingsWithBlock:`, or overwrite scene mutableSettings without a fresh exact address-bounded extract + device-safe lifecycle proof.
- Independent source `DFSceneHost.commitSceneGeometry:` now only corrects **three selector dispatches** with guarded, separately counted `child2/child3/main2`, preserving Portrait and 0.30s resize debounce.
