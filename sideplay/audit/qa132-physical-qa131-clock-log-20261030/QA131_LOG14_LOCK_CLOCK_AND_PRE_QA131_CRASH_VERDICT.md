## Engineering verdict / limitations
**Verified**: QA131 established the primary iPhone screen's display clock goes from 24–28 ticks/5s to sustained **0** under `protectedData=0`, even while the leased YouTube app process keeps emitting clock diagnostic messages and its UIKit state is reported active. This is substantially stronger real-device evidence motivating an independent BKS scene/display state experiment. It does **not** prove the display clock itself is the root cause of missing Play, because no remote YouTube Play-button event/Control action receipt or actual playback state is logged. Screen backlight and input acceptance are distinct.
