## What .91 actually does; limitations

- Same **one DuoFace package**, no separate CarBridge requirement. First-party independent in-process `DFNativeMapPaneCoordinator.dylib` is scoped to `CarPlay` / `CarPlayApp` executables, idle by default. The existing DuoFace iPhone app has one opt-in panel `Bố cục > Thử nghiệm bản đồ CarPlay native`, buttons `Bản đồ bên trái`, `Bản đồ bên phải`, `Khôi phục giao diện Maps`. Controller tries a guarded SAME-PROCESS UIKit adopt of the existing real `DBApplicationSceneViewController` only after validating FBScene owner, hierarchy/window, screen and native Dock measured area. Can refuse with explicit reason. It does NOT copy OmniCar binary/source/license; does NOT inject SpringBoard for this new coordinator; does NOT clone `CPWindow`, call FBS foreground/background indiscriminately, fake map tiles or apply arbitrary zoom.
- **NOT VERIFIED ON IPHONE:** .91 installed successfully; Google Maps CarPlay-native map tiles actually present inside left/right DuoFace pane, simultaneously phone YouTube displayed and correct orientation, active navigation remains uninterrupted, CarPlay Customize Maps stays enabled, Dock/Home stability or absence of SpringBoard crash.
- There is a genuine iOS16 scene-owner limitation: earlier 46 user snapshots showed Maps native scene rebind to DuoFace scene with SAME native VC, not two simultaneously visible host panes. Native VC adoption can be rejected or may not yield the user's target visual result. CI compile/Sileo success does not prove UI or navigation success.
- No automated installation was performed, no device logs from .91 received. This is an **experimental QA update**, not OmniCar full-equivalence proof.
