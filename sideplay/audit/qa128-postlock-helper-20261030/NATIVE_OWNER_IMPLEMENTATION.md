# Independent native-owner candidate — 2026-10-30

Implemented on fix/duoface-postlock-settings-20261030, atop exact original Home trace 7c528a19 and previously SDK-checked postlock source acfe2c68. This is source work, not a signed release or device PASS. Public QA128 remains unchanged.

## Changes and purpose

- Existing CarPlay Dock receiver installs only runtime-present DBRootStatusBarViewController/CARRootStatusBarViewController homeButtonUp: with exact void/object ABI and saved original forwarding once. Every present named class must have the verified hook for retention to be eligible. Missing method/ABI/hook mechanism disables retention; existing stop behavior remains.
- Home persists a sticky revocation for the current UUID before forwarding original. App and SpringBoard consume a separate notification, checking UUID again. SpringBoard hides/releases its existing UI through the existing DFStopProbe cleanup. Dock restoration remains scoped to its saved Dock. Delayed notifications cannot revoke a newer UUID. The preexisting generic stop callback now checks current validity before tearing down a newer session.
- A read-only native owner witness runs in CarPlay every 0.5s. It enumerates existing DBApplicationSceneViewController instances; requires exactly one foreground, visible candidate, typed object metadata, com.duoface.native.scenehost identity, native scene ID and live view/controller ancestry. Existing applicationInfo/proxyApplicationInfo/scene/sceneHandle paths come from the project's first-party owner snapshot; runtime getters are verified before invocation. Missing metadata or an unrecognized host fails closed.
- Native ownership is acquired only while the app's own foreground pulse is fresh. The same exact controller, native scene ID, host scene ID and session UUID must remain current. Background cannot acquire/change that binding. The witness carries 1.25s expiry and is independently refreshed only while those conditions and Home-hook coverage still hold. Foreign/ambiguous/missing native owner publishes inactive evidence.
- CPTemplate Background now attempts to retain only that already authenticated owner. App pulse records HostBackground and HostSceneID. For Background, the shared validator requires the independently fresh native lease; for ordinary foreground, the existing 2.5s app-heartbeat expiry remains. This allows an already authorized background session to survive phone-app suspension without extending an unverified timer. No native attestation means stop exactly as before.
- SpringBoard command send, active-owner checks, watchdog, scene foreground/underlock/postlock admission and Dock receiver use the shared validator. Watchdog remains at 0.5s and never creates ownership. Explicit disconnect/tombstone and display cleanup are preserved. QA128 manual observer crash repair, .90 rotation, .92 divider and .120 geometry source remain in place.
