## Important correction to avoid a false root cause

DFYouTubeOrientationRelay.m increments applied only when rotating/resizing; a previously saved window with matching size+portrait still receives layout invalidation then CONTINUES without incrementing applied or adding measurements. Thus windows=0 + layoutRefreshed=1 is consistent with a valid window. It does NOT prove a hidden/missing YouTube window, loss of input, or a broken geometry ACK. Do not fix this number by forcing reflow repeatedly.
