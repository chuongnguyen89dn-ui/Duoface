## QA6 source-level direct explanation (VERIFIED CODE, not hardware correlation)
- Repo `chuongnguyen89dn-ui/Duoface`, branch `feature/duoface-dock-crop-livewindow-20261020`, file `sideplay/mytweak-native-bridgeqa/DFCPNativeBridgeQA.m`, method `tickNativeDashboardSourceYield:`: when CarPlay ACK supplies normalized measured screen content, it resizes the *SpringBoard-created external source UIWindow* from full screen to content and records original. `sourceYieldExperimentEnabled` is gated by third `NativeSidebarTrial` opt-in. `BOOL expired=(NSDate.date.timeIntervalSince1970-self.yieldSince>45)` is hard-coded; after expiration, `self.exhaustedYieldSession=self.yieldSession` and `restoreYieldedSourceWindow:` restores original **full-screen frame**. Code also restores if ACK/bridge session changes, source frame is changed externally, or `HostFullscreen` is selected. Therefore an eventual reversion from Dock-visible content to full screen is **EXPECTED** under an unchanged session after 45sec; do not present it as a new unexplained native CarPlay behavior. Check device log `source-window-cropped-after-native-ack`, `source-window-crop-restored reason=45sec-lease-expired`; other reasons should be logged separately.
- `sideplay/mytweak-independent-v1a/MTBridgeCoordinator.m` creates an independent external `UIRootSceneWindow` via `FBSDisplayConfiguration` from SpringBoard, making window/frame/level susceptible to foreign scene composition. `sideplay/mytweak-independent-v1a/prototype/MTCPDashboardOwner.m` runs within the native CarPlay host process to measure existing `DBStatusBarWindow`/usable rect and ACK it. QA6 STILL has the legacy `drawViewHierarchyInRect` remote-image fallback/transport from QA5; successful crop may expose original live window and preserve native touches, but dashboard receiver ACK is not itself proof of touch. Do not strip existing window lifecycle or change fullscreen policy without regression tests.
- Recorded physical frame in QA log: full `507.333333 × 240`, normal content `{{45,0},{462.333333,240}}`; this is device-specific, **not** a universal fixed Dock width.

## Priority A — Open source / public source with CLOSEST matching iPhone jailbreak problem

### 1. CarSurf — https://github.com/pavunato/carsurf
- **Public source, licensing restriction:** GitHub REST repo metadata `license=null`; inspected complete tree `main` and found **NO LICENSE**. This is source-visible, NOT automatically freely reusable/open-source-licensed. Study API/ideas, do not copy code or distribute derivatives absent affirmative permission/license clarification.
- Author claims iOS 15–18, tested iPhone X iOS16.7.12 with RootHide + iPhone11 iOS18.5 rootless. Neither was tested by us with user's rootless/DiPlay stack. README says one arbitrary iPhone app has a native live `UIWindowScene` with touch/keyboard/video. **No claim it implements DuoFace's 2-up multi-app split panel.**
- `sbtweak/CSCarLaunch.m`: operates from **CarPlay process**, captures `DBWorkspace` with `DBDashboardWorkspaceOwner`, and invokes `DBApplicationController.sharedInstance`, `DBMutableWorkspaceStateChangeRequest.activateApplication:`, `DBWorkspace.requestStateChange:` — native workspace launch flow, not a foreign display UIWindow pinned at a guessed level.
- `sbtweak/CSSystem.m`, `sbtweak/CSSceneManifestSpoof.m`, `sbtweak/CSCarKitPolicy.m`: iOS16/17 and iOS18 admission paths differ; LaunchServices in older releases and CarKit for iOS18. LS hooks can cause SpringBoard safe mode if installed on wrong process/version; author explicitly includes kill switch. Do NOT blind-copy these private hooks into DuoFace.
- `apptweak/CSSceneBridge.m`: **important geometry algorithm** `CSCarViewportForWindow` works with native `UIWindowScene.coordinateSpace.bounds` and safeAreaInsets; before EVERY measurement it first restores the logical window to scene bounds to avoid cumulative inset shrink/creep, then measures **all 4 edges** and applies scale/layout; logging includes scene/screen/native/currentMode and safe insets. This is more reliable than our one-time static ACK and 45s root-window-crop trial, but only directly valid when we have a genuine app-associated CarPlay `UIWindowScene`.
- `apptweak/CSSceneBridge.m` handles scene role `UIWindowSceneSessionRoleCarPlay` and conversion from templates to app window role for bridged apps; README warns rewriting role *after* template scene construction can crash CarPlay apps. For independent DuoFace follow native scene ownership and user split host rather than mimicking entitlement; test with rootless iOS16.

### 2. CarPlayEnable / carplay-cast — https://github.com/EthanArbuckle/carplay-cast
- **Actual OSI-friendly license:** `LICENSE` and REST repo metadata `Apache-2.0` (obligations to retain attribution/license and NOTICE if relevant). Source tree has `src/CRCarplayWindow.mm`, `src/hooks/CarPlay.xm`, `src/hooks/SpringBoard.xm`, `src/hooks/UIApplication.xm`, `src/common.h`. README targets **iOS14+** but implementation is historical, not verified compatible with user's iOS16.7 rootless. Control package is `com.cortex.carplayenable 1.0.1`, architecture `iphoneos-arm`.
- `src/CRCarplayWindow.mm` creates independent SpringBoard `UIRootSceneWindow` and explicitly calls `setupDock`, creating a **CUSTOM self-rendered Dock** with home/fullscreen/rotate buttons and reserves `CARPLAY_DOCK_WIDTH`. Thus **NOT** a reference for guaranteed native Apple Dock. Valuable as an archival example of scene hosting and live touch, not for our 'only real native Dock' requirement.
- `src/hooks/CarPlay.xm` does interact with real `appDockViewController` and `_refreshAppDock` to update CarPlay recents, and posts events into SpringBoard. Historic [issue #58](https://github.com/EthanArbuckle/carplay-cast/issues/58) shows SpringBoard safe-mode crash. Distinguish native Dock management from a custom Dock in the window; no unreviewed production hook.

## Priority B — Real CarPlay template app source, helpful for lifecycle but NOT arbitrary dual iPhone apps
- **Apple Coastal Roads sample**: https://developer.apple.com/documentation/carplay/integrating-carplay-with-your-navigation-app — actual Apple sample, `CPTemplateApplicationScene` with `CPMapTemplate`, `CPWindow`; system owns UI buttons/bar; base map canvas not directly tap/drag interactive. Example community mirror https://github.com/g4rb4g3/CoastalRoads (repo advertises MIT; verify exact sample licensing before copying).
- **React Native CarPlay**: https://github.com/birkir/react-native-carplay — **MIT**, template-based `setRootTemplate`; does not host arbitrary apps/2-panel native UIKit touch.
- **Flutter CarPlay**: https://github.com/oguzhnatly/flutter_carplay — CarPlay template API only; entitlement needed and not a generic external UIWindow/scene host. License check before any reuse.

## Priority C — Android/Linux/Rust **head-unit receiver** projects, different end of CarPlay protocol
- **DiPlay**: https://github.com/shihabal3amri/DiPlay — Android APK that receives iPhone projection; relevant to user's Android/DiPlay hardware, **not** iOS native Dock scene ownership.
- **CarLink**: https://github.com/F-e-n-y-x/CarLink — Android receiver combining DiPlay+DiAuto, **AGPL-3.0**.
- **OpenAutoLink**: https://github.com/mossyhub/openautolink — AAOS receiver, GPLv3.
- **LIVI**: https://github.com/f-io/LIVI — Linux/macOS head-unit receiver, GPL-3.0-or-later, has system dock position settings but works at ACCESSORY side, not app scene inside iPhone.
- **CatPlay**: https://github.com/catplay-labs/catplay — Rust iAP2/AirPlay/MFi protocol + accessory firmware; NOT UIKit/split app host.
- All receiver sources primarily control connection/framing/input over wire, not iOS `DBWorkspace`/iPhone's `UIWindowScene`. Licensing may require source sharing and MFi identity issues are separate; do not ingest APK accessory credentials.
