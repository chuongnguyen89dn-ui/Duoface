## Confirmed gap with current DuoFace (not yet a proven sole cause)
- Original `homeButtonUp:` synchronous call chain goes `stopBridging` / `requestDismiss` within the Home dispatch, before its return (e.g. line 4224 -> 4225 -> 4226). Current first-party `DFCarPlayOwnerObserver.h:127-164` **posts an asynchronous Darwin stop notification** before forwarding original Apple Home callback; the actual SpringBoard host stop and Dock reset are in separate notification consumers (`DFHomeStandalone144.m`, `DFNativeDockSync147.h`). Log26 measured Home -> standalone stop **29.365–52.047 ms** for five correlated bridge exits. This is a **real ordering/lifecycle design difference**: publishing a notification is not the same as a synchronous manager dismissal inside CarPlay.
- Current Log26 still has 5 verified Dashboard receiver requests (Facebook 2, Safari 2, YouTube 1), all native `dashboard/workspace` checks pass, 5 bridge stops and Dock restore; the user nonetheless reports Home reaches CarPlay Home instead of the app chooser. This rules out repeating the older **wrong dashboard receiver** repair as the next answer. Log26 had no named Music/Calendar reference, whereas this new ORIGINAL trace does.
- **Hypothesis, not verified cause:** notifying the SpringBoard owner and returning to Apple's Home handler before the native CarPlay/bridge owner has an equivalent synchronous state transition may cause a different page decision. Need correlate CarPlay Home entry/return, actual live dashboard scene and stop completion in the first-party trace; an app chooser page may be an independent first-party UI route rather than a Dock-state toggle. Do NOT imitate proprietary methods by copying them; implement an independent owned state machine after confirming the page destination.
- The original trace actually proves `DBRootStatusBarViewController.homeButtonUp:` is invoked and its argument/receiver are real. It **does not** prove that Apple Home itself sends users to the vendor's app-selection screen, and does not authorize intercepting/swallowing Apple's Home callback.
