## What ACTUALLY repaired the successful QA128 candidate
Fresh GitHub compare `a8b334e...f84e27a...` identifies **just one runtime class's changed behavior** between QA127 and QA128: `sideplay/duoface-native-scene-host/DFSceneLifecycle.m` (+15/-11), a new `DFManualObserverContract.h` (+13) and its header comment. The operative code was introduced in commit **`4d770510ab137a403dacaddf39f445074625dee8`**:
1. Earlier `DFIsOwnedManualSceneObserver` depended on `ownedScene()`, an **on-screen presentation lease** that becomes nil when the hosted view/window is hidden, detached or not yet attached. The hook would then forward its manual `SBAppViewController sceneHandle:didUpdateSettingsWithDiff:previousSettings:` callback into Apple's **automatic** lifecycle path even when the controller had `automatesLifecycle=NO`.
2. QA128 independently separated **manual callback ownership** from **presentation visibility**: the controller must be registered, be on main thread, have its *current identical* `sceneHandle`, `sceneIfExists` non-nil, ABI-valid `automatesLifecycle` returning NO. For that specific controller, `DFManagedSceneObserver` consumes the automatic observer event. Foreground/lock rewriters still require separately owned live visible presentation.
3. This was a concrete **source-contract fix**, with C test `manual_observer_contract_test.c` executing **128** combinations and iOS16 SDK syntax gate. QA128 phone-level improvement was reported by user; there is **no evidence that QA128 fixed GOFA by changing its width/height formula**.

**Critical new direct comparison:** exact source extraction `static BOOL DFIsOwnedManualSceneObserver(...)` through `DFManagedSceneObserver(...)` is **byte-for-byte identical** (2,181 characters) between QA128 and QA133. Therefore the original successful callback-ownership fix **has NOT been removed**. Reapplying it, changing arbitrary GOFA scale constants or simply copying QA128 `DFNative12Chrome.m` would NOT address the newly introduced conditions by itself.
