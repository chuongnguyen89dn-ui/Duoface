## 1. Separate two completely different problems

**A. Native Apple CarPlay Home roster/launch**: whether an app has an icon on Apple's genuine app-icon grid, how it is selected, admitted, tapped and launched independently. For native Maps/Waze/GOFA, iOS owns the existing CarPlay declaration, icon policy and native scene. For selected *ordinary iPhone apps* DuoFace previously built an opt-in standalone bridge. An entry in the DuoFace `My Apps` picker or a nonnull `FBSApplicationLibrary` record does not prove an Apple Home icon or working click.

**B. Native Maps inside DuoFace's two-pane display**: reuse the actual Maps CarPlay scene owned/presented in the `CarPlay` process; place its real native controller and host view into exactly one geometrically verified pane; maintain the independent phone/Waze other pane and scene owner after native foreground handoff. This is NOT fulfilled by simply publishing Maps on Apple Home and is NOT equivalent to scaling `SBAppViewController` / `initWithApplicationForMainDisplay:` or capturing turn-list UI.

The user requirement since **2026-10-28** is explicitly Maps **enabled** in native CarPlay, with genuine map tiles, native touches/navigation and a split pane. An OFF/ON stock setting was only an experimental control for QA182, not a permanent product workaround. Do not declare that OmniCar changed iOS Customize based on a log string mentioning its own Settings UI.
