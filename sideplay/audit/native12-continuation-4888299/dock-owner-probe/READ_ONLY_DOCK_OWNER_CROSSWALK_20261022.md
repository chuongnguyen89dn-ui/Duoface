## Smallest safe new engineering artifact
`DFNativeDockOwnerReadOnly.m` here is an **unpackaged, uncompiled, manually callable diagnostic function**, not a deployed tweak. It only executes when explicitly invoked on the main thread inside an existing `CarPlay`/`CarPlayApp` process. It enumerates *that process's* UIWindowScenes and existing UIWindows, capturing class/root-controller names, actual screen/window bounds, level, hidden state and activation state. `DBDockWindow`, `DBDashboardRootViewController`, `DBDashboardWorkspaceOwner` are probed with `NSClassFromString`, never instantiated, invoked or hooked. It never writes Dock, UIWindow, app state, session files, or gives positive ACK. No constructor or automatic start. Absence of `DBDockWindow` does not establish absence of Apple Dock under other classes.

**Provenance of diagnostic:** staged file commit `07cc18ce03204aa8c8cf882207d124670d7462cc`. Static author-time assertions: main-thread/process gates, no `constructor`, no `performSelector`, no UIWindow property assignment and no positive DockHiddenAck all checked TRUE in this ChatGPT/GitHub session. **No clang compile, injection, device log or runtime class proof has occurred.** This file is deliberately outside `sideplay/duoface-native-scene-host/**`, so it does **not** trigger the branch's auto-package workflow on its own.
