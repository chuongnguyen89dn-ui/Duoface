1. Touch architecture still differs from the archived reference. sideplay/audit/duoface-116-touch-ownership-20261029/ORIGINAL_TOUCH_ATTACHMENT_CALLSITES.md records CBWindow.createWindows at 0xb1064 selecting a base, then registering CBTouchPassThroughRootSceneWindow overrides for hitTest:withEvent:, pointInside:withEvent:, and sendEvent:. In current DFNative12Chrome.m, makeWindow instantiates the external window class directly; comments deliberately omit that window-level layer after the earlier .117 regression. Current recall instead depends on pane-view hitTest and app-side relays. ensureWakeGates additionally declines wake on unknown/visible keyboard, ineligible hosted bundles, focus and modal state. Matching method names and updating logo alpha is not proof that remote app touches reach these callbacks. This is a verified source/reference divergence, NOT a proved sole device root cause. 2. Native map library reader and launcher do not use the same lookup contract. sideplay/native-carplay-scene-v1/DFNativeMapCatalog.h tries applicationLibrary/_applicationLibrary/appLibrary/_appLibrary plus object ivars. Ivar fallback may succeed; therefore actual lookup failure remains a hypothesis until the device's catalog/launch rejection is read. Do not assert this alone fixes Waze.
3. Maps and GOFA are separate routes in DFCarPlayAppRoute178.h. GOFA uses phone AppBridge; Google Maps, Apple Maps and Waze use a guarded native coordinator. GOFA working proves nothing about the native path. The picker now sends a request, but launch-context/native declaration/physical pane checks can still reject it. Read actual DFNativeMapPaneCoordinator Reason instead of removing guards or faking Applied.
4. The outside-DuoFace CarPlay Home requirement was not completed by the picker fix. DFHomePublisher136Core.m has its own enabled/selected/native-library gates and explicitly skips records with an existing native declaration (NATIVE_DECLARATION_EXISTS_OS_HOME_ICON_NOT_MANAGED_BY_DUOFACE). The archived OmniCar analysis, sideplay/audit/omnicar-iphone-picker-20261029/DUODASH_OMNICAR_COMBINED_ARCHITECTURE_RESEARCH_20261029.md, establishes separate appBridgeApps, homeScreenShownApps/homeScreenHiddenApps and split-picker flows.
