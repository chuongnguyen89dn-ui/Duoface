## CONFIRMED exact original function/call chain

1. **Original hook installer**: `0x6f5c` imported `_dlsym` resolves literal `BKSDisplayServicesSetScreenBlanked`. `0x6f80` imported `_MSHookFunction` replaces with callback at `0x777c` and stores original pointer at `0x3ea10`.
2. **Conditional live-pane predicate**: `0x777c` only enters special branch on caller-requested blank==1 (`0x7790 cmp w0,#1`). Original ObjC class/relative method-table decoding proves `+[ABHost shared]` IMP `0xa9e8` and `-[ABHost count]` IMP `0xaaa0`. The `-count` method invokes `-[ABHost panes]` at `0xaaac bl 0x26580`, followed by selector `count` at `0xaabc bl 0x25420`: **ABHost count is the count of its `panes` collection**. `0x77c0 cbz x21,0x780c` forwards untouched original arg if pane count==0. When pane count>0, special branch executes.
3. **Special branch first blanks**: `0x77cc mov w0,#1; 0x77d0 blr x8` calls saved ORIGINAL BKS with blank=1. The hook does **not** unconditionally suppress system blank.
4. **Schedules one-second restoration**: `0x77d4 mov x0,#0` and `0x77d8/0x77dc` build **0x3b9aca00 = 1,000,000,000 nanoseconds** as second argument. `0x77e0` is imported **`_dispatch_time`**. `0x77e4/0x77e8` loads imported **`__dispatch_main_q`** through GOT `0x34290`. `0x77ec/0x77f0` creates arg x2 = global block literal `0x347d0`. `0x77f4` imported **`_dispatch_after`**, so original code schedules a **main-queue callback +1s**.
5. **Callback executes original UNBLANK**: Actual local `__const` literal `0x347d0` has `__NSConcreteGlobalBlock` ISA (dyld chained import ordinal 179), flags `0x50000000` (global + signature), invoke pointer to `0x9688`, block descriptor `0x34610` (size 32). This block's direct code `0x968c` loads saved original BKS pointer, then `0x9690 mov w0,#0; 0x9694 br x1` invokes ORIGINAL **UNBLANK=0**. Thus the `0x9688` code has a verified callback owner: **the global block passed by original hook to `dispatch_after`**, not an unrelated CarPlay disconnect method.
6. Separate block `0x347b0`, invoke `0x958c`, is passed at `0x7214` and may relate to `AVExternalDevice` callbacks; it is **NOT the one-second unblank block** and does not prove disconnect behavior.
